# 🎓 منصة مركز الوسيط التعليمية (الإصدار الأول)

منصة ويب لبيع صلاحية الوصول إلى محاضرات الفيديو ومشاهدتها، فيها حسابات للطلاب، ولوحة إدارة، ونظام صلاحيات حقيقي يُتحقق منه على الخادم، ورموز تفعيل مع QR. واجهتها عربية بالكامل (RTL) ومصممة للهاتف أولًا.

> هذا المجلد مشروع مستقل عن موقع المواعيد الموجود في جذر المستودع، ويُنشر كمشروع Vercel منفصل، فالموقع الحالي لا يتأثر به.

## ما الذي يعمل الآن

| الميزة | الحالة |
|---|---|
| الصفحة الرئيسية: الهوية، السنوات والمواد (تبويبات + تصفية حسب الفئة/القسم)، الأساتذة | ✅ |
| إنشاء حساب (الاسم، الهاتف، البريد، كلمة المرور)، دخول، خروج، جلسة آمنة لمدة 30 يومًا | ✅ |
| استعادة كلمة المرور: بالبريد (عند ضبط Resend)، أو برابط يولّده المدير ويرسله عبر واتساب | ✅ |
| لوحة الطالب: بياناته، موادي المفعّلة وتاريخ انتهائها، كل المواد مع حالة (مفعّلة / جزئية / غير مفعّلة) | ✅ |
| صفحة المادة والمحاضرات مرتبة، مع قفل واضح للمحاضرات غير المفعّلة، ومحاضرات مجانية للمعاينة | ✅ |
| مشغّل فيديو عبر مسار بث محمي، يتحقق من الجلسة والاشتراك في كل طلب، مع علامة مائية متحركة باسم الطالب | ✅ |
| لوحة الإدارة: الطلاب، الاشتراكات، الأساتذة، السنوات والأقسام والفئات، المواد، المحاضرات وترتيبها، الحزم | ✅ |
| تفعيل أو إلغاء مادة لطالب، إيقاف حساب، منح صلاحية مدير، سجل نشاط لكل طالب | ✅ |
| رموز التفعيل: دفعات، عدد استخدامات، مدة صلاحية، آخر موعد للاستخدام، تعطيل رمز، بطاقات QR للطباعة | ✅ |
| تطبيق Android (Capacitor) يبنيه GitHub تلقائيًا، ويمنع لقطات الشاشة وتسجيلها | ✅ (يحتاج رابط المنصة بعد نشرها) |
| **جهاز واحد لكل حساب طالب**: الدخول من جهاز آخر يُرفض، والنقل يحتاج موافقة الإدارة (التفاصيل في [docs/DEVICE-BINDING.md](docs/DEVICE-BINDING.md)) | ✅ |
| **الإدارة**: فقط البريدات في `ADMIN_EMAILS`، وبعد إدخال كلمة مرور الإدارة `ADMIN_PASSWORD` | ✅ |

البيانات الأولية: السنوات الأربع، والفئتان A وB للسنة الثانية، والأقسام الثلاثة للسنة الرابعة، و17 مادة وأستاذان. كلها البيانات الرسمية المأخوذة من `lib/seed.js` في جذر المستودع. **المحاضرات الموجودة تجريبية** (عنوانها "محاضرة تجريبية"، وفيديوهاتها مقاطع رياضية مولّدة)، وتستطيع حذفها واستبدالها من لوحة الإدارة.

## التقنيات، ولماذا اخترتها

- **Next.js 16 + React 19 + TypeScript:** الواجهة ومنطق الخادم في مشروع واحد، لكن منفصلان: كل منطق البيانات والصلاحيات في `src/server/` ولا يصل إلى المتصفح (`server-only`).
- **PostgreSQL + Drizzle ORM:** قاعدة بيانات علائقية حقيقية مع ترحيلات (migrations) مكتوبة بـ SQL. تعمل مع أي مزوّد (Neon، Supabase، خادم خاص)، فلا ارتباط بشركة واحدة.
- **مصادقة مبنية داخل المشروع:** كلمات المرور مشفّرة بـ scrypt، وجلسات في قاعدة البيانات بكوكي httpOnly، وحد للمحاولات. اخترت ذلك بدل Firebase أو Supabase Auth لثلاثة أسباب: قاعدة واحدة فيها الحسابات والاشتراكات معًا، وتحكم كامل لاحقًا في ربط الجهاز وتراخيص التشغيل دون اتصال، وعدم الاعتماد على خدمة قد تُحجب في سوريا.
- **Tailwind CSS 4** مع خط IBM Plex Sans Arabic مستضاف داخل المشروع (لا اعتماد على Google Fonts).
- **Capacitor 8** لتطبيق Android/iOS: يغلّف المنصة نفسها، ويسمح بإضافة كود Kotlin/Swift أصلي للميزات التي يحتاجها الهاتف (التشفير، التنزيل، العمل دون اتصال).

## النشر من الهاتف (مرة واحدة، حوالي 10 دقائق)

تحتاج حسابًا على Vercel، وهو نفس الحساب الذي ينشر موقع المواعيد الحالي.

1. افتح **vercel.com/new** واختر المستودع **Alwasit** ثم **Import**.
2. في **Root Directory** اضغط **Edit** واختر **`platform`**، وسمِّ المشروع مثلًا `alwasit-platform`.
3. افتح **Environment Variables** وأضف:
   - `ADMIN_EMAILS` = بريدات حسابات الإدارة مفصولة بفواصل.
   - `ADMIN_PASSWORD` = كلمة مرور الإدارة (تُطلب بعد تسجيل الدخول بحساب مدير).
   - `APP_URL` = رابط المشروع، مثل `https://alwasit-platform.vercel.app`.
4. اضغط **Deploy**. سيفشل أول نشر برسالة `DATABASE_URL غير مضبوط`، وهذا متوقع.
5. من صفحة المشروع: **Storage** ← **Create Database** ← **Neon (Postgres)** ← الخطة المجانية ← **Create** ← **Connect** للمشروع. هذه الخطوة تضيف `DATABASE_URL` تلقائيًا.
6. **Deployments** ← النقاط الثلاث بجانب آخر نشر ← **Redeploy**. سيُنشئ البناء الجداول ويضيف البيانات الأولية تلقائيًا.
7. افتح رابط المنصة وسجّل حسابًا (أو ادخل) بأحد البريدات في `ADMIN_EMAILS`، ثم أدخل كلمة مرور الإدارة لتفتح **لوحة الإدارة**.

> تعديل `ADMIN_EMAILS` يسري عند الدخول التالي للحساب. حذف بريد من القائمة يسحب منه الإدارة فورًا.

**اختياري، لإرسال رسائل الاستعادة بالبريد:** أنشئ حسابًا مجانيًا على resend.com، ثم أضف `RESEND_API_KEY` و`MAIL_FROM` (مثل `Alwasit <noreply@your-domain.com>`، ويحتاج نطاقًا خاصًا موثّقًا). بدون ذلك تعمل الاستعادة من لوحة الإدارة: صفحة الطالب ← **إنشاء رابط استعادة** ← أرسله له عبر واتساب.

## تطبيق Android (APK) دون لابتوب

يبني GitHub Actions الملف تلقائيًا عند كل تعديل في `platform/`.

1. بعد نشر المنصة: في GitHub افتح المستودع ← **Settings** ← **Secrets and variables** ← **Actions** ← تبويب **Variables** ← **New repository variable**، باسم `PLATFORM_URL` وقيمة رابط المنصة.
2. **Actions** ← **Platform (tests + Android APK)** ← **Run workflow**.
3. بعد انتهاء البناء (حوالي 6 دقائق) تجد `alwasit-platform.apk` في **Releases**، أو في **Artifacts** داخل صفحة التشغيل.

النسخة الحالية **debug**: تُثبّت وتعمل، لكنها موقّعة بمفتاح اختبار. قبل النشر على Google Play نضيف مفتاح توقيع خاصًا بك كـ Secret.

## هيكل المشروع

```
src/app/(site)/      صفحات الطالب والزائر: الرئيسية، الدخول، اللوحة، المادة، المشغّل، التفعيل، الحساب
src/app/admin/       لوحة الإدارة (كل صفحة وكل إجراء يتحقق من دور المدير على الخادم)
src/app/api/stream/  بث الفيديو بعد التحقق من الصلاحية
src/server/          منطق الخادم: قاعدة البيانات، المصادقة، الصلاحيات، الرموز، الفيديو، الإجراءات
src/components/      مكونات الواجهة
drizzle/             ترحيلات قاعدة البيانات (SQL)
scripts/             الترحيل والبيانات الأولية (تعمل تلقائيًا عند البناء)
private-media/       الفيديوهات التجريبية (خارج public، فلا تصل إليها إلا عبر مسار البث)
android/             مشروع Android الأصلي (Capacitor)
tests/               اختبارات الوحدة، واختبار شامل في متصفح حقيقي
docs/ROADMAP.md      خطة الميزات المتقدمة
docs/DEVICE-BINDING.md  ربط الحساب بجهاز واحد: التصميم والحدود والتطوير الأصلي
```

## الأمان (ما هو مطبّق)

- كل صلاحية يُتحقق منها **على الخادم**: صفحات الإدارة، وكل إجراء إداري، ومسار البث في كل طلب Range. إخفاء الأزرار ليس هو الحماية.
- رابط الفيديو الحقيقي لا يُرسل للمتصفح إطلاقًا، والبث مرفوض لغير المسجّلين (401) ولغير المشتركين (403)، ويتوقف فور إلغاء الاشتراك.
- كلمات المرور مشفّرة بـ scrypt، وتُحفظ بصمة SHA-256 لرموز الجلسات والاستعادة فقط، لا الرموز نفسها.
- حد للمحاولات على الدخول والتسجيل والاستعادة وإدخال الرموز، محفوظ في قاعدة البيانات.
- تغيير كلمة المرور أو إيقاف الحساب أو تغيير الدور يُخرج الحساب من كل الأجهزة.
- تفعيل الرمز يتم داخل معاملة مع قفل الصف، فلا يمكن تجاوز عدد الاستخدامات حتى مع طلبات متزامنة.
- لا مفاتيح أو كلمات مرور داخل الكود. كل الإعدادات في متغيرات البيئة (انظر `.env.example`).

## للمطوّرين

```bash
cp .env.example .env         # ضع DATABASE_URL لقاعدة Postgres
npm install
npm run db:migrate           # الجداول + البيانات الأولية
npm run dev                  # http://localhost:3000
npm run typecheck && npm test
npm run build && PORT=3100 npm start &
BASE_URL=http://localhost:3100 node tests/e2e/run.mjs   # 31 سيناريو في متصفح حقيقي
```

لتعديل قاعدة البيانات: عدّل `src/server/db/schema.ts`، ثم شغّل `npm run db:generate` لإنشاء ملف ترحيل جديد.
